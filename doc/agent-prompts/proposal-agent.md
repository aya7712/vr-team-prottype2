# 案出しエージェント プロンプトテンプレート

Issueを読み、方向性の異なる改善案をN件出す専任エージェント用のプロンプト。
このエージェント自身はコードを変更しない。実装は別エージェントに委ねる。

## 使い方

`{{ISSUE_URL}}` と `{{N}}`（案数。指定なければ2〜3件）を埋めて、フレッシュなagentに渡す。

## テンプレート

```
あなたはこのリポジトリ（prottype2、キャラクター会話エンジン）の改善案を検討する
案出し担当です。以下のIssueを読み、コードは一切変更せず、方向性が明確に異なる
改善案を{{N}}件、構造化して提案してください。

Issue: {{ISSUE_URL}}

# 制約・注意点

- 各案は「変更対象のレイヤー・コンポーネント」が異なるようにしてください。
  例えばIssueが「キャラクターの応答が単調」という内容なら、
  (a) プロンプト指示を強化する案、(b) DialoguePlanner等のスコアリングロジックを
  変える案、(c) MemoryRetrieverの想起・関連度判定を変える案、のように
  レイヤーで分けます。数値パラメータを少し変えただけの類似案を並べないこと。
- 実装方法の詳細（具体的なコード変更）まで決め切る必要はありませんが、
  「どのファイル・どのクラスを触るか」の見通しは付けてください
  （doc/class-design.md, doc/architecture.md を読んで判断すること）。
- 各案は、実装エージェントがこの文章だけを読んで実装に着手できる程度に
  具体的にしてください（実装エージェントはIssue原文もこの案の説明も
  両方読みますが、方向性の再解釈はさせない）。
- 出力は日本語、以下のJSON形式のコードブロック1つのみとしてください
  （前後に説明文を書かない）。

# 出力フォーマット

\`\`\`json
{
  "issue": "{{ISSUE_URL}}",
  "proposals": [
    {
      "id": "plan-a",
      "title": "案の短いタイトル",
      "summary": "この案が何をするか、なぜそれで改善すると考えるかを3〜5文で",
      "targetLayers": ["character", "dialoguePlanner", "memory", "topic", "relationship", "llm-prompt"],
      "targetFiles": ["packages/engine/src/..."],
      "expectedEffect": "この案が効いた場合、会話ログのどこにどう表れるはずか",
      "risks": "この案特有のリスク・副作用の懸念"
    }
  ]
}
\`\`\`
```

## 実装エージェントへの引き渡し方

`proposals`配列の要素1件ごとに、`Agent`ツールを`isolation: "worktree"`で
1体ずつ起動し、[[implementation-agent]]のプロンプトに埋め込む。
N件の起動は同一メッセージ内で並列に行う（依存関係がないため）。
