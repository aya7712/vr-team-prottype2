# changelog運用ルール

`doc/todo.md`は運用終了しました。並行して複数の実装エージェントがworktreeで同時にPRを
作る運用のため、単一ファイルへの追記はコンフリクトの原因になります。以降の変更管理は
このディレクトリで、**1変更につき1ファイル**を新規作成する形に統一します。

## ファイル名

`YYYYMMDD-HHMMSS-<slug>.md`（作成時刻のUTC + 変更内容を表す短い英語スラッグ）。

例: `20260902-143000-improve-tone-check.md`

日時を含めることで、並行して作業する実装エージェント同士でファイル名が衝突しません。
既存ファイルの編集や番号の採番管理は不要です。

## テンプレート

新規変更に気づいたら、このディレクトリに以下の形式で1ファイル作成するだけで済みます。

```markdown
# <変更タイトル>

- 日時: <ISO8601>
- 対応Issue/PR: <URL>

## 概要
（この変更が何をするか）

## 原因・期待する効果
（問題の原因をどう捉えたか、なぜこの変更で改善するか）

## 変更対象ファイル
- packages/...

## 自己レビュー
（未対応の指摘がある場合のみ記載）
```
