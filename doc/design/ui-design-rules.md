# AI会話エンジン UIデザインルール（プロトタイプ版）

対象参照: `features.md`（F9 モニタリング／ログUI）, `class-design.md` 14章, `data-design.md`

## 1. デザインコンセプト

- **シンプルでモダンなUI**を基本方針とする。開発・デバッグ用ツールであり装飾性より視認性・情報密度のコントロールを優先する。
- 派手な演出（過度なアニメーション、グラデーション多用、装飾的なイラスト等）は避け、余白・タイポグラフィ・最小限のカラーで情報の階層を作る。
- UIの主目的は「なぜこの発話が選ばれたか」を追跡できること（`features.md` F9.3）なので、**データが主役、UIコンポーネントは脇役**という意識で設計する。

## 2. カラーシステム

### 2.1 基本パレット（ニュートラル）
UI全体の地・枠線・本文テキストはニュートラルなグレースケールで統一する。

| トークン | 用途 |
|---|---|
| `--color-bg` | ページ背景 |
| `--color-surface` | カード・パネルの背景 |
| `--color-border` | 区切り線・枠線 |
| `--color-text` | 本文テキスト |
| `--color-text-muted` | 補助テキスト（タイムスタンプ、ラベル等） |
| `--color-accent` | UI操作系（ボタン、リンク、選択状態等）の共通アクセント。キャラクター色とは独立させる |

ライト/ダーク双方に対応できるよう、上記トークンをCSS変数として定義し、`prefers-color-scheme`で値のみ切り替える（構造・コンポーネントは共通）。

### 2.2 キャラクターカラーの適用（本ドキュメントの主眼）
- `character_def/design/main/*.yaml` の `color` フィールド（例: `char_a` = `#FFC20E`）を**キャラクターを識別する唯一の色情報源**とする。UI側で独自に色を割り当てない。
- `CharacterDefLoader`（`class-design.md` 12章）がこの`color`値も`characters_cache`に取り込み、`server`のAPIレスポンス（キャラクター一覧等）に含めて`ui`へ渡す。
- キャラクターカラーは**セリフ関連のUI要素にのみ**使用し、UI全体の背景やナビゲーション等の構造要素には使わない（4体分の色が同時に主張しすぎて視認性が下がるのを防ぐため）。

適用箇所（F9.1〜F9.3で共通のルール）:

| UI要素 | 適用方法 |
|---|---|
| チャットバブル（F9.1 リアルタイム会話ビュー） | 発話者のキャラクターカラーを**バブルの左端ボーダー（4px程度のアクセントライン）**および**発言者名のテキスト色**に使用する。バブル背景はニュートラル（`--color-surface`）のまま統一し、可読性を優先する |
| 発言者アイコン/アバター | 背景色にキャラクターカラーを使用し、頭文字またはキャラ略号を白/黒（コントラスト比で自動判定）で表示する |
| パラメータダッシュボード（F9.2）のキャラクター別カード | カードのヘッダー部分の下線または左ボーダーにキャラクターカラーを使用する |
| Relationship Matrix（F9.2） | 行/列見出しのキャラクター名にキャラクターカラーを使用する。マトリクスのセル自体は関係性数値の強弱を別の中間色スケール（後述2.3）で表現し、キャラクターカラーと混同しないようにする |
| Dialogue Actスコア内訳（F9.3） | 表・グラフの主要な数値表現には使わず、「誰の発話か」を示すヘッダー部分のみに限定して使用する |
| ログ一覧（F9.4） | 各ターン行の発言者名にキャラクターカラーを使用する |

- キャラクターカラーは**そのままの16進値を使う**（デザイン側で明度調整・アルファ合成をする場合も、元の`color`値からCSS上で`color-mix()`等を用いて導出し、独自の色を新規に定義しない）。
- キャラクターカラーが背景色として使われる場合（アバター等）、テキストとのコントラスト比 **4.5:1以上**（WCAG AA相当）を確保できるよう、テキスト色（白/黒）を自動判定するユーティリティ関数（`getReadableTextColor(hex: string): '#000000' | '#FFFFFF'`）を`ui/src/components`に用意する。

### 2.3 データ表現用の色（キャラクターカラーと分離する）
- Topicのenergy/novelty/life、関係性のtrust/intimacy等、**数値の強弱を表す色**はキャラクターカラーと独立した中間色スケール（例: 単色の濃淡、または`dataviz`スキルの指針に沿った連続スケール）を使う。
- 「キャラクターを表す色」と「数値の大小を表す色」を混同すると誤読を招くため、この2系統は常に別の色相・別のUI領域で使う。

## 3. タイポグラフィ・レイアウト

- フォントはシステムフォント（`-apple-system, "Segoe UI", "Hiragino Sans", sans-serif`等）を用い、Webフォント読み込みによる依存を増やさない。
- 情報密度が高い画面（F9.3レイヤー別計算過程、F9.4ログ一覧）は等幅フォント（数値・JSON表示部分）と可変幅フォント（日本語テキスト）を使い分ける。
- レイアウトは**左：会話タイムライン、右：パラメータ/計算過程パネル**の2カラムを基本形とする（F9.1とF9.2/F9.3を同時に見比べられるようにする）。
- 余白は8pxグリッドを基準にする（8/16/24/32px）。

## 4. コンポーネント方針

- UIコンポーネントライブラリは軽量なものに限定する（プロトタイプの依存最小化方針、`architecture.md` 3章と整合）。装飾を作り込むのではなく、素のHTML要素+最小限のスタイリング（CSS ModulesまたはTailwind等、実装時に1つ選定）で構成する。
- グラフ表示（Topicエネルギー推移、関係性マトリクス等）は`dataviz`スキルの指針（色のルール、軸・凡例・ツールチップの扱い）に従う。
- ローディング状態・空状態（セッション未開始等）は最小限のプレースホルダーテキストで表現し、凝ったスケルトンUIは作らない。

## 5. レイヤー別計算過程ビュー（F9.3）の表示ルール

- 「なぜこの発話行為が選ばれたか」を一目で追えることを最優先する。`DialogueActScore`（`class-design.md` 3章）は、Act名・BaseWeight・各Modifier値・最終スコア・確率を**表形式**で並べ、選択されたActを行のハイライト（背景色を薄いアクセント色に）で強調する。
- LLMへの送信プロンプト全文は折りたたみ可能なコードブロック（等幅フォント）で表示し、常時全文表示はしない（情報過多を避ける）。

## 6. アクセシビリティ・実装補足

- キャラクターカラーは4体分が同時に画面に並ぶため、色だけに依存せず**キャラクター名のテキストを必ず併記**する（色覚特性への配慮、`requirements.md`の非機能要件には未記載だが実装時の基本方針とする）。
- ダークモード時もキャラクターカラーの視認性を保てるよう、背景トークン（`--color-bg`, `--color-surface`)側で十分なコントラストを確保し、キャラクターカラー自体は変化させない（色の同一性を優先）。
